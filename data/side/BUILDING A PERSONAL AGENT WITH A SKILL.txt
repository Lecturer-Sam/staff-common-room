## 1. The Core Concept: Agent + `SKILL.md` + Command Execution

A `SKILL.md` file acts as the **brain's instruction manual**. It tells the agent:
- **What it can do** (its capabilities)
- **What tools/commands** are available
- **How to reason** about when to use them
- **Safety boundaries** (what it must *not* do)

### Minimal Architecture

```
┌──────────────┐      ┌───────────────────┐      ┌──────────────┐
│   You (User) │─────▶│   Agent Runtime   │─────▶│  LLM (Brain) │
│   "Do X"     │◀─────│  (Python/Node)    │◀─────│  Ollama / HF │
└──────────────┘      └────────┬──────────┘      └──────────────┘
                               │
                    ┌──────────▼──────────┐
                    │   SKILL.md (loaded  │
                    │   into system prompt│
                    │   at startup)       │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │  Command Executor   │
                    │  (subprocess, bash, │
                    │   API calls, etc.)  │
                    └─────────────────────┘
```

### Example `SKILL.md`

```markdown
# Agent Skills

## Identity
You are my personal DevOps assistant.

## Available Commands
- `git status` — Check repo state
- `docker ps` — List running containers
- `kubectl get pods` — Check Kubernetes pods
- `deploy <service>` — Run the deploy script

## Rules
- NEVER run `rm -rf` or `DROP TABLE`
- Always confirm destructive actions with the user
- Explain what you're about to run before running it
```

### Simplified Python Agent

```python
import subprocess, json, requests

# 1. Load the skill definition
with open("SKILL.md") as f:
    skill = f.read()

# 2. Build the system prompt
system_prompt = f"""You are an AI agent. Follow these skills strictly:
{skill}

When you want to execute a command, respond in this JSON format:
{{"action": "run", "command": "<shell command>"}}

If you just want to talk, respond normally."""

# 3. Talk to the LLM (via Ollama in this case)
def ask_llm(user_message):
    response = requests.post("http://localhost:11434/api/chat", json={
        "model": "llama3",
        "messages": [
            {"role": "system", "content": system_prompt},
            {"role": "user",   "content": user_message}
        ],
        "stream": False
    })
    return response.json()["message"]["content"]

# 4. Parse & execute
def agent_loop(user_input):
    reply = ask_llm(user_input)
    try:
        parsed = json.loads(reply)
        if parsed.get("action") == "run":
            cmd = parsed["command"]
            print(f"⚡ Executing: {cmd}")
            result = subprocess.run(cmd, shell=True, capture_output=True, text=True)
            print(result.stdout)
            # Feed result back to LLM for interpretation
            return ask_llm(f"Command output:\n{result.stdout}\nSummarize this.")
    except json.JSONDecodeError:
        pass
    return reply

# 5. Run it
print(agent_loop("Are my Docker containers healthy?"))
```

## 2. 🦙 Ollama's Role: **The Local LLM Engine**

| Aspect | Detail |
|---|---|
| **What it is** | A runtime for running open-source LLMs **locally** on your machine |
| **Key job** | Receives your `SKILL.md` + user query, returns reasoning & commands |
| **API** | Exposes an OpenAI-compatible REST API at `localhost:11434` |
| **Privacy** | Everything stays on your hardware — no data leaves your machine |
| **Models** | `llama3`, `mistral`, `qwen2.5`, `codellama`, `phi3`, `gemma2`, etc. |
| **Cost** | Free (uses your GPU/RAM) |

### What Ollama does for your agent specifically:

```
Your Agent  ──HTTP POST──▶  Ollama API  ──loads──▶  Llama 3 (local weights)
                            localhost:11434
```

- **Startup:** `ollama pull llama3` → `ollama serve`
- **Your agent calls it** just like any API — no cloud keys needed
- **Tool-calling support:** Newer Ollama models (Llama 3.1+, Qwen 2.5) support structured tool-use natively, meaning your agent can define tools formally and the model will call them reliably

### Ollama with native tool calling (newer approach):

```python
tools = [{
    "type": "function",
    "function": {
        "name": "run_shell",
        "description": "Execute a shell command",
        "parameters": {
            "type": "object",
            "properties": {
                "command": {"type": "string"}
            }
        }
    }
}]

response = requests.post("http://localhost:11434/api/chat", json={
    "model": "llama3.1",
    "messages": [{"role": "user", "content": "Check disk usage"}],
    "tools": tools
})
# The model will return a tool_call instead of raw text
```

## 3. 🤗 Hugging Face's Role: **The Model Ecosystem & Toolkit**

Hugging Face plays a **broader, multi-layered** role:

| Role | How It Helps Your Agent |
|---|---|
| **Model Hub** | Browse & download 500k+ models (text, code, reasoning). Find the *best* model for your agent's task |
| **`transformers` library** | Load models **directly in Python** without Ollama — full control over inference |
| **Inference API (cloud)** | If you don't have a GPU, use HF's hosted API as your agent's brain |
| **Fine-tuning** | Train a model *specifically* on your SKILL.md patterns so it follows instructions better |
| **GGUF exports** | Many HF models are converted to GGUF format → which Ollama can then run locally |
| **Datasets** | Find datasets to evaluate or improve your agent's command-generation accuracy |

### Option A: Use HF `transformers` directly (no Ollama)

```python
from transformers import pipeline

agent_brain = pipeline(
    "text-generation",
    model="Qwen/Qwen2.5-Coder-7B-Instruct",
    device_map="auto"
)

prompt = f"""<|system|>
{skill}
<|user|>
Deploy the frontend service
<|assistant|>"""

output = agent_brain(prompt, max_new_tokens=200)
```

### Option B: Use HF Inference API (cloud, no GPU needed)

```python
from huggingface_hub import InferenceClient

client = InferenceClient("mistralai/Mistral-7B-Instruct-v0.3", token="hf_...")
reply = client.chat_completion(
    messages=[
        {"role": "system", "content": skill},
        {"role": "user", "content": "List my running pods"}
    ]
)
```

### Option C: HF → Ollama pipeline (most common)

```
Hugging Face Hub          Ollama              Your Agent
     │                      │                     │
  Download GGUF ──────▶  ollama create  ──────▶  API calls
  (e.g., Qwen2.5)        (custom model)          with SKILL.md
```

```
│  Safety:     Allowlist of commands + human confirm   │
└─────────────────────────────────────────────────────┘
```

---

## ⚠️ Critical Safety Notes

1. **Never give the agent blind `shell=True` access** — use an allowlist of commands
2. **Sandbox execution** (Docker container, VM, or `firejail`)
3. **Add a human-in-the-loop** confirmation step for destructive commands
4. **Validate and sanitize** all LLM-generated commands before execution
5. The LLM *will* hallucinate commands — your executor must catch errors gracefully
